# Cobertura dos requisitos pela regressão

Cada identificador encontrado nos ficheiros de `docs/requisitos/` tem aqui uma linha. O nome da regressão é estável: troca-se o prefixo `REQ` por `REG`. O plano da coluna é quem acrescenta o teste ao manifesto. O estado `agora` só aparece quando esse teste já corre neste repositório. O estado `pendente` espera pelo plano dono.

A tabela tem 141 linhas, uma por requisito.

Nesta versão, as linhas de produto estão `pendente`. A suite que já corre verifica o arnês, os exemplos JSON, esta tabela, a ausência de pesos e a secção Buracos da matriz. Esses testes não fecham um requisito de produto; vivem no manifesto sem linha nesta tabela.

Quem implementa um plano acrescenta as linhas `REG` no fim de `tests/regressao/manifesto.txt` e não edita esta tabela. O pull request de fecho, depois dos planos PLN-01 a PLN-21, passa cada linha a `agora` e faz falhar a integração se algum requisito ficar sem regressão no manifesto.

O verificador de esquemas JSON dos exemplos é um subconjunto da biblioteca padrão, descrito em [docs/desenvolvimento/regressao.md](../desenvolvimento/regressao.md). Não usa a biblioteca `jsonschema`.
